CI pipeline and artifacts

The image build is defined in .github/workflows/build-image.yaml.

Triggers and tags

Git ref Published image tag
Push to develop latest-dev
Push to main latest
Tag v<version> <version>, checked against release.yaml

release.yaml supplies image_registry, image_prefix, image_name, and image_version. The resulting image reference is <image_registry>/<image_prefix>/<image_name>:<tag>.

Build stages

  1. Resolve the image tag and validate release tags against release.yaml.
  2. Build image.tar with Kaniko without pushing.
  3. Generate a CycloneDX JSON SBOM with Trivy 0.76.1 and retain it for 30 days.
  4. Preserve the full application and OS inventory for downstream security jobs.
  5. Scan licenses, format the report, and upload the review artifact.
  6. Push the archive with Skopeo and record its digest.
  7. Attach the CycloneDX SBOM to that exact digest with ORAS.
  8. Pull that exact digest, generate NOTICE, and attach it with LICENSE using ORAS.

The image job declares contents: read and packages: write. Registry publication uses GITHUB_TOKEN; optional Docker Hub authentication uses the dockerhub-username and dockerhub-token secrets.

After successful publication, Grype scans the attached SBOM and the default-branch build submits supported application packages to the dependency graph. See image security monitoring for permissions, settings, coverage, daily/manual scans, and retrieval instructions. Scans do not remove already published images.

validate.yaml runs unit/ORAS integration tests, Actionlint, shell syntax checks, and a strict MkDocs build on pull requests and branch pushes.

Outputs

Output Location and purpose
image.tar Build-job workspace; image archive used for scans and publication
sbom.cdx.json image-sbom Actions artifact (30 days) and OCI referrer on the published image digest
license-report.json, license-report.txt license-review Actions artifact, retained for 30 days
pushed.digest, image.digest Build-job workspace; digest records used during publication
LICENSE, NOTICE Registry attachment to the pushed image digest

The notice attachment type is application/vnd.eoap.license-notices.v1. Its files are not placed inside the runtime image.

License scan settings

The full license scan uses --scanners license --license-full, retains all severities, and sets --exit-code 0. Findings do not block publication; scanner and report-generation errors fail the job.

The README records these default Trivy classifications:

Severity Classification
CRITICAL Forbidden
HIGH Restricted
MEDIUM Reciprocal
LOW Notice, Permissive, or Unencumbered
UNKNOWN Unrecognized

These are scanner labels, not a project-approved policy. See license evidence for interpretation.
